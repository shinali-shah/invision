# Playback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tap-to-record web app (iPhone + glasses mic) that transcribes both voices with Muse Voice Transcribe, analyzes the user's listening with rules + Muse Spark, returns one reviewed coaching note per conversation, and shows a memory view with a pattern and a weekly next step.

**Architecture:** One Node 24 server (Express 5 + `ws`) holds the API key, proxies browser PCM audio to Muse's realtime WebSocket, stores conversations in SQLite (`node:sqlite`), and runs the agent pipeline. A no-build vanilla-JS frontend in `public/` captures mic audio through an AudioWorklet (24 kHz PCM16) and renders transcript, note, memory and logs. With no `MODEL_API_KEY` (or `MOCK=1`) every Muse call is replaced by a deterministic mock, so the full demo runs offline.

**Tech Stack:** Node 24 (ESM), Express 5, `ws` 8, `node:sqlite`, `node:test`, native `fetch`, vanilla JS + AudioWorklet, ngrok for iPhone HTTPS.

**Spec:** the team spec, v2 (Oct 24 2026)

## Muse API facts (verified against dev.meta.ai docs, 2026-10-24)

- Base URL `https://api.meta.ai/v1`, key in env `MODEL_API_KEY`.
- **Realtime ASR:** `wss://api.meta.ai/v1/asr/realtime`. No HTTP auth header; first text frame within 10 s:
  `{"authorization":{"accessToken":"Bearer <KEY>"},"audioEncoding":"PCM_24KHZ","model":"muse-voice-transcribe-1.0","mode":"DIARIZATION","languageBias":["English","Spanish"]}`.
  Server replies with `{sessionId}` (no `type`). Then binary frames of s16le mono 24 kHz PCM, 80 ms = 3840 bytes, sent at real-time pace, never >5 s ahead. End with text `{"type":"endStream"}`, then read until close 1000.
  Events (dispatch on `type`, ignore unknown): `transcript{transcript,final,audioProcessedMs}`, `speechStart{turnId,audioProcessedMs}`, `speechEnd{turnId,audioProcessedMs}`, `speechComplete{turnId,transcript,audioProcessedMs}`, `speaker{label,audioProcessedMs}` (one per turn, DIARIZATION only), `audioProgress`, `error{message,sessionId,errorCode?}`. Close codes: 1008 bad config/pacing, 1011 backend (retry), 1013 rate limit.
- **File ASR (fallback):** `POST /v1/asr/transcribe`, `multipart/form-data` parts `request` (JSON `{"model":"muse-voice-transcribe-1.0","audioEncoding":"WAV","mode":"DIARIZATION","languageBias":[...]}`) and `audio` (mono 16-bit WAV, 16/24 kHz, ≤10 min, ≤32 MB), `Authorization: Bearer`, `Accept: application/json` → `{sessionId,transcript,audioDurationMs,turns:[{turnId,startMs,endMs,transcript,speaker?}]}`.
- **Muse Spark:** `POST /v1/chat/completions`, `Authorization: Bearer`, model `muse-spark-1.3`, roles `developer`/`user`, `reasoning_effort` ∈ minimal|low|medium|high|xhigh (never `none`), `max_completion_tokens`, `response_format: {type:"json_schema", json_schema:{name, schema, strict:true}}` (strict ⇒ every object `additionalProperties:false` and all props required). Do **not** send `stop`, `n>1`, `logprobs`, `temperature`+`top_p` together. Result JSON string in `choices[0].message.content`.

## Global Constraints

- Node ≥ 24; ESM only (`"type":"module"`); runtime deps limited to `express@5`, `ws@8`. Tests use `node:test` + `node:assert/strict`; no test framework deps.
- The API key never reaches the browser. Audio is never written to disk; it lives only in the per-socket buffer and is dropped when the socket closes ("raw audio deleted after").
- Context tags are exactly `family`, `friend`, `networking`. Focus copy (verbatim from spec): family → "Phrases to keep the conversation going, cultural context for what they said, a vocab list from words that came up"; friend → "Follow-up questions, remembering what matters to them, following through"; networking → "Clear questions, listening before pitching, a drafted follow-up message".
- Coaching is about the user's behavior only. The other person's lines are used only as response signals (answer length, stories shared after a question). No score, rating or label of the other person anywhere in UI, notes or patterns.
- Every coaching note is written in second person, at most 3 sentences, and passes the reviewer before display.
- Pattern statements never call the user good/bad at conversation and always cite their numbers.
- Every agent has the spec's fallback: NLP → rule counts only; Coach → show raw signal counts, no advice; Pattern → signal table only; Next step → fixed list; Reviewer → drop note, show counts. The demo never dead-ends.
- Recording starts only after the user confirms they told the other person (`consentConfirmed: true`); tap starts, tap stops; on-screen recording indicator.
- Memory stores the other person's name exactly as typed, nothing else about them.
- Demo language pair is configurable: `DEMO_LANGUAGES` env, comma-separated, default `English,Spanish` (spec open decision).
- Muse model IDs come from env with defaults: `MUSE_SPARK_MODEL=muse-spark-1.3`, `MUSE_ASR_MODEL=muse-voice-transcribe-1.0`.
- No git remote and no push. Local commits only.

## Review Focus

1. **Diarization returns one speaker or `unknown` labels** (noisy room, single mic, spec cites ~17.5% DER) → pipeline still completes: other-person signals are 0, note still produced from the user's own signals, no crash. Test in Task 2.
2. **Muse returns an error, times out, or returns malformed JSON mid-pipeline** → each agent falls back as specified and the conversation still finishes with something on screen. Tests in Tasks 3 and 5.
3. **Stopping immediately / no speech captured** (0–1 turns) → process responds 200 with note `{status:"dropped", reason:"too_short"}` and UI shows "Too short to coach — try a longer conversation." Test in Task 5.
4. **iPhone opened over plain http or mic permission denied** → UI shows a specific message (needs https via ngrok / allow microphone) instead of a dead button. Test in Task 6 (`micErrorMessage`).
5. **Deleting a conversation** → its turns, signals and note are gone, it no longer feeds `recentNotes` or the pattern, and the memory view recomputes. Test in Task 5.

## Shared types (every task uses these names exactly)

```js
// Turn
{ turnId: number, speaker: string /* 'A'|'B'|...|'unknown' */, text: string, startMs: number, endMs: number }

// Signals (rules fields always present; AI fields null when source === 'rules-only')
{ userQuestions, userTurns, otherTurns, userTalkMs, otherTalkMs,
  userTalkShare /* 0..1, 2dp */, otherAvgAnswerWords /* after user questions, 1dp, 0 if none */,
  followUps: number|null, reflections: number|null, storiesAfterQuestions: number|null,
  questions: [{ turnId, isFollowUp: boolean|null, replyTurnId: number|null, replyWords: number, storyShared: boolean|null }],
  source: 'muse-spark' | 'rules-only' }

// Note
{ text: string|null, suggestion: string|null, citedTurnIds: number[],
  status: 'shown'|'rewritten'|'dropped', reason?: 'too_short'|'reviewer'|'coach_failed', source: 'muse-spark'|'fallback' }

// Conversation
{ id: string /* crypto.randomUUID() */, tag: 'family'|'friend'|'networking', otherName: string,
  createdAt: string /* ISO */, seeded: boolean, turns: Turn[]|null, userLabel: string|null,
  reflection: string|null, signals: Signals|null, note: Note|null }

// Pattern
{ statement: string, metric: 'followUps'|'userQuestions'|'otherAvgAnswerWords'|'userTalkShare', counts: number[] } | null

// NextStep
{ id: number, text: string, status: 'proposed'|'accepted'|'changed'|'dismissed', createdAt: string }
```

  - `GET /api/memory` → `{ conversations: Conversation[], pattern: Pattern, nextStep: NextStep|null, signalTable: [{id, createdAt, tag, otherName, userQuestions, followUps, otherAvgAnswerWords, userTalkShare}] }`
